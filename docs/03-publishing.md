# Публікація об'єкта

## Як додати об'єкт

1. Створити `src/content/work/<slug>/` — `<slug>` унікальний,
   kebab-case.
2. `index.yaml` — структурні поля (розділ 4a моделі): `type`,
   `status`, `art_direction`, `cover`, `year`, `data_mode`, і за
   потреби `context`, `endpoint`, `owner`, `last_checked`,
   `source_repo`, `build_ref`, `data_snapshot_date`, `data_fields[]`.
3. `uk.md` і `en.md` — **обидва**, кожен з frontmatter (`title`,
   `summary`, за потреби `tags[]`) і markdown body нижче. `body`
   обов'язкове для `type: CASE` і `type: EDITORIAL`.
4. `cover.jpg` (або інший растровий формат) — заглушка достатня,
   фінальний ассет не потрібен на цьому кроці.
5. `npm run build`. Якщо збірка падає — повідомлення називає slug і
   номер правила (`[5.1] ...`, `[5.7] ...`) з `src/content.config.ts`.

## Поля й правила

Повний перелік полів і їхніх значень — `01-content-model.md`, розділ 4.
Правила збірки, які їх перевіряють, — розділ 5 того самого документа,
реалізовані в `workSchema.superRefine()` (`src/content.config.ts`).

Швидка довідка, що вимагає що:

| Якщо... | тоді... | правило |
|---|---|---|
| `data_mode: LIVE_BUSINESS` | збірка падає завжди | 5.1 |
| `context: ALTACO` і `status: LIVE` | збірка падає | 5.1 |
| `status` LIVE/DEMO і є `endpoint` | треба `build_ref` | 5.2 |
| `status: LIVE` | треба `owner` | 5.4 |
| `data_mode` не NONE і не SYNTHETIC | треба `data_snapshot_date` | 5.4 |
| `type` CASE або EDITORIAL | треба `body` в обох мовах | розділ 4 |
| відсутній `uk.md` або `en.md` | збірка падає | 5.7 |

## Що робити, коли демо зупиняється

Демо на Neurica — вбудований артефакт (`build_ref`), не з'єднання з
живим сервісом (розділ 4, `build_ref`; правило 5.2). Коли джерело
демо перестає існувати чи оновлюватися:

1. Змінити `status` з `LIVE`/`DEMO` на `FROZEN`.
2. Прибрати `endpoint`, якщо він був — сторінка більше не обіцяє
   інтерактивності.
3. `body` й текст лишаються — `FROZEN` це "було інтерактивним, тепер
   запис", не видалення (розділ 3 моделі, `status: FROZEN`).

Це саме той сценарій, заради якого існують дві осі (`type` + `status`,
рішення 004): об'єкт лишається `CASE`, просто змінює стан.

**Автоматичне пониження.** Якщо `status: LIVE`, а `last_checked`
старіший за 45 днів — збірка сама знижує статус до `FROZEN` і виводить
warning у консоль (правило 5.3, реалізовано в `.transform()` схеми).
Це не помилка збірки: сторінка публікується, просто вже не як `LIVE`.
