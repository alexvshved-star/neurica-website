# Інформаційна архітектура

Структурний крок: ролі сторінок, шаблони за типом об'єкта, правило
масштабу картки, порядок стрічки, правило двох виходів на EONYX.
Оформлення (типографічні композиції, motion, hover) — окремий крок 05.

## Ролі сторінок

`/` і `/work` навмисно різні за роботою, яку виконують — не два
входи до того самого переліку.

| Маршрут | Роль | Набір | Порядок | Компонент |
|---|---|---|---|---|
| `/` | Стрічка — кураторський зріз | `feature: true` + найсвіжіші, разом ≤ 8, без `ARCHIVE` | published desc, фінально хронологічний | `HomeView.astro` → `selectHomeFeed()` |
| `/work` | Індекс — повний перелік | усе крім `ARCHIVE`, включно з `FROZEN` | published desc | `WorkIndexView.astro` → `sortByPublishedDesc()` |
| `/work/[slug]` | Сторінка об'єкта | — | — | `WorkDetailView.astro` + 4 шаблони |
| `/about` | Позиціонування, без маркетингу | — | — | `AboutView.astro` |
| `/archive` | Тільки `ARCHIVE` | `ARCHIVE` | published desc | `ArchiveView.astro` |
| `/404` | Вихід на `/` і `/work` | — | — | `NotFoundView.astro` |

`/work/[type]` як статичні сторінки-фільтри зарезервовано (рішення
020), не реалізовано: при п'яти об'єктах це UI без задачі. Коли
з'явиться потреба — статичні маршрути, не клієнтський віджет
(індексуються, працюють без JS, не додають полів вводу).

`/archive` не в навігації — доступна з підвалу й за прямим посиланням.

### `selectHomeFeed()` — точний алгоритм

```
featured = items.filter(feature === true)
rest     = sortByPublishedDesc(items.filter(feature !== true))
selected = featured + rest.slice(0, 8 - featured.length)
return sortByPublishedDesc(selected)
```

Featured об'єкти не групуються окремим блоком — фінальне сортування
за `published` тримає стрічку хронологічною, `feature` лише впливає
на те, хто потрапляє у вибірку (і на масштаб картки, нижче).

## Шаблони об'єкта

Один шаблон на всі типи змішує різний за природою вміст. Чотири
шаблони, спільний каркас (`WorkDetailView.astro` — тонкий диспетчер):

**Спільне для всіх** (`WorkDetailView.astro` напряму): `title`, рядок
метаданих `TYPE · STATUS · рік` (5.5 придушує `STATIC`), `summary`,
`cover` (крім `EDITORIAL`), унизу — попередній/наступний об'єкт за
`published` і повернення в `/work`.

| Тип | Компонент | Порядок |
|---|---|---|
| `CASE` | `CaseTemplate.astro` | `RuntimeNotice` (якщо DEMO) над прозою → проза задача→підхід→результат |
| `PROTOTYPE`, `TOOL`, `EXPERIMENT` | `PrototypeTemplate.astro` | `RuntimeNotice` одразу під summary → проза (опційна) |
| `VISUAL_STUDY` | `VisualStudyTemplate.astro` | послідовність `media[]`, короткий опційний текст |
| `EDITORIAL` | `EditorialTemplate.astro` | тільки проза, без `cover` у тілі |

Чотири фікстури покривають чотири різні шаблони (рішення 040:
`organic-intelligence` видалено, стартовий набір — `altaco-catalog`,
`agent-workflow`, `synthetic-structures-01`, `what-neurica-is`, по
одному на `CASE`/`PROTOTYPE`/`VISUAL_STUDY`/`EDITORIAL`).

### Блок демонстрації (`RuntimeNotice.astro`)

Один блок, не розділений застереження й посилання — розділені,
до застереження не доходять (клікають одразу):

```
DEMO · дані від 12.08.2026
Демонстраційний набір. Не робоча система.
[Відкрити демо →]
```

Для `FROZEN` — рядок замість посилання: інтерактивна частина
відключена, сторінка лишається як опис. Для `LIVE` з `endpoint` —
мінімальний варіант без застереження (на каркасі жодна фікстура цим
не користується — `context: ALTACO` не може бути `LIVE`, правило 5.1).

## Картка (`WorkCard.astro`) і рядок (`WorkIndexRow.astro`)

`WorkCard.astro` — `/` (`cover`, масштаб через `data-scale`) і
`/archive` (`compact` prop — без cover, без масштабної варіації,
однорідний рядок).

`/work` (design-brief, крок "вузький список") — окремий компонент
`WorkIndexRow.astro`, не `WorkCard` `compact`: мініатюра (72×54
mobile / 88×64 desktop, однаковий розмір для всіх напрямків, не
`--image-ratio` — той лишається карткам стрічки й обкладинці
об'єкта), `TYPE`, заголовок, summary в один рядок (`text-overflow`),
рік праворуч, тонка лінія-розділювач між рядками. Окремий компонент,
не третій режим `WorkCard` — розмітка (мініатюра+рік у рядку)
достатньо інша, а спільний CSS-клас ризикував би зачепити
`/archive`, який має лишитися без змін.

### Правило масштабу — виводиться, не задається

```
feature === true        → large
status in (LIVE, DEMO)  → medium
інакше                  → small
```

`feature` — єдине ручне поле (розділ 4, рішення 021), максимум 3
одночасно; більше — warning на збірці (`content.config.ts`, loader),
не fail. На `/` масштаб виражається як цільова висота рядка
(`--row-height`, `HomeView.astro`), не кількість колонок сітки —
крок 05b замінив ранню grid-column-заглушку на editorial wall:
ширина картки = висота рядка × пропорція її `art_direction`, колонок
немає взагалі. Деталі механізму — рішення 041, `05-decisions.md`.

Чергування арт-дирекшенів (5.6) застосовується до фінального порядку
карток і на `/`, і на `/work`.

## Навігація

**Шапка** (`Nav.astro`): `NEURICA` + підпис `by EONYX` (окреме
посилання на eonyx.net) зліва, `WORK` / `ABOUT` посередині, перемикач
мови справа. `/archive` у шапці немає.

**Підвал** (`Footer.astro`): знак, `by EONYX` → eonyx.net, `/archive`,
поточний рік.

**Правило двох виходів.** Рівно два посилання на eonyx.net на весь
сайт — підпис у шапці й підпис у підвалі. Заявка про співпрацю —
поведінка eonyx.net; сторінки об'єктів не мають окремих CTA.

## Метадані

Кожна сторінка (`Base.astro`): `title`, `description` (з `summary`
для об'єктів), `og:title`, `og:description`, `og:type` (`article` для
об'єктів, `website` інакше), `og:image` (з `cover`; заглушка
`/og-default.jpg` для індексів), канонічний URL, повний набір
`hreflang` (уже було реалізовано в кроці 01, перевірено на нових
маршрутах).

`sitemap.xml` виключає `ARCHIVE`-об'єкти (`astro.config.mjs`, filter
на основі `status` із `index.yaml` — фікстури порушень у
`src/_fixtures/` і так ніколи не потрапляють у колекцію).
