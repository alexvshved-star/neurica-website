## PR №8 — статус пунктів `REVIEW_TASKS.md`

(`index.html`, `index-en.html`, `splash.js`), який реланч замінив на
поточну Astro-реалізацію. Відсутність старого файла сама по собі не
означає вирішення проблеми — кожен пункт звірено з поточним кодом.

## Залишкові задачі (без дублікатів)

### R1 — Немає CI-перевірки узгодженості SEO/i18n
- **Проблема:** неузгодженість canonical/hreflang, sitemap чи полів Netlify-форм може потрапити в `main` непомітно — CI цього не ловить.
- **Дія:** додати легкий скрипт (наприклад, `scripts/check-seo-i18n.mjs`), що перевіряє парність `hreflang`/`canonical` для uk/en у зібраних сторінках, наявність усіх не-ARCHIVE сторінок у `sitemap.xml`, і узгодженість `name`/`bot-field` у Netlify-формах; підключити як блокуючий крок `validate.yml`.
- **Критерій готовності:** крок CI провалюється при штучно внесеній неузгодженості й проходить на чистому дереві.

### R2 — Застарілий коментар про кешування JS у `netlify.toml`
- **Проблема:** коментар біля правила `/*.js` досі буквально каже "перенесено без змін з попереднього сайту", хоча джерело оригінальної проблеми (`splash.js` зі стабільним іменем) вже не існує; те, що твердження коментаря зараз правильне — випадковий наслідок Astro/Vite-збірки, а не свідомо задокументований факт.
- **Дія:** переписати коментар, вказавши, що хешування імен файлів виконує Astro/Vite build, без згадки видаленого `splash.js`.
- **Критерій готовності:** коментар описує реальний поточний механізм кешування без посилання на неіснуючий файл.

### R3 — README без явних розділів "Deployment"/"Forms"
- **Проблема:** контрибʼютор, що читає лише `README.md`, не бачить самостійного розділу про деплой чи обробку форм — потрібно переходити за посиланням у `docs/04-architecture.md`.
- **Дія:** або додати в `README.md` короткі розділи "Деплой" і "Форми" з посиланням на `docs/04-architecture.md` для деталей, або явно визнати поточну структуру (`README.md` → `docs/04-architecture.md`) достатньою і закрити пункт без змін README.
- **Критерій готовності:** рішення зафіксоване власником (розділи додані, або пункт явно закритий як "посилання достатньо").
